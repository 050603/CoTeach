# ADR 0010：原始数据与可重建资源分层存储

- 状态：已采纳
- 日期：2026-09-11

## 背景

课程脚本、课堂学习记录、用户上传与 AI 生成的二进制产物原先使用相同备份
策略。实际数据中，课堂 TTS 占课堂目录约 95%，而每段音频的原文、动作 ID、
语言及 provider/model/voice/timing 配方已存在课堂 JSON 中。把脚本和音频
同时放入每个历史快照造成高额重复存储，也延长恢复传输时间。

`FileAsset` 过去还把 PPTX 原件与 PDF 课堂预览当成两个无关系的文件，仅在
`Resource.metadata` 中保存预览 ID；这使备份器无法可靠判断哪个文件是原始
数据、哪个文件可重建。常规上传的 `sha256` 也没有写入，恢复后无法核验内容。

## 决策

1. 持久数据分为 `REQUIRED`、`REGENERATE`、`EPHEMERAL` 三类。
2. 用户上传、课堂脚本、学习证据和当前没有完整重建配方的图片/视频始终备份。
3. 服务器生成的课堂 TTS 不进入默认快照；课堂 JSON 是其恢复配方。排除前
   必须确认本地音频引用拥有非空 `speech.text`，否则保留该课堂全部音频。
4. `FileAsset` 记录来源、自引用依赖、重建配方、更新时间与 SHA-256。PPTX
   课堂 PDF 预览标记为 `REGENERATE` 并关联原始 PPTX。
5. 每个快照包含机器可读的重建队列。恢复是两阶段过程：先恢复核心数据，
   再以限流、可续跑方式重建派生资源。
6. 不把“AI 生成”直接等同于“可丢弃”。只有输入、配方和可用生成器都持久化
   后，资源才能改为 `REGENERATE`；因此现阶段课堂生成图片、视频和封面仍备份。

## 结果

默认快照显著缩小，Restic 仍继续对保留文件做加密、去重和保留策略管理。
核心数据恢复不再等待大体积 TTS 下载，但完整课堂媒体恢复时间会受到供应商
配额影响。恢复后的语音保持语义一致，不承诺与旧音频逐字节一致。

该分层也为后续图片/视频优化提供了约束：先持久化版本化 prompt、模型、输入
素材与后处理参数，再改变其备份策略，不能仅依据目录名或文件后缀排除。
