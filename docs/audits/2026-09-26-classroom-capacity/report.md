## 未通过项与上线限制

1. **集中提交延迟**：本轮归档 80 次 P95 2826.801ms，超过 2000ms；外部作品提交 80 次 P95 2818.561ms，同样按保存回执目标列为未通过。全部操作完成且文件/业务版本正确，不能因此称性能通过。归档原子性与 DOCX 锁外生成已修复，剩余耗时来源仍需分段测量，不能凭静态代码认定根因。
2. **后台单段批注可靠性和质量**：40 次首次请求有 1 次返回 503 / `AI_REVIEW_INVALID_STRUCTURE`，独立首败率 **2.5%**，超过 0.5%；同一请求 ID 的有界重试已恢复，原失败、完整模型输出和决策仍保留。另有 9 次模型建议因证据不独立被策略拦截，实际创建 31 条批注。策略拒绝无效批注是正确保护，但教学批注质量未达验收要求，不能把 no-comment 或 HTTP 200 当作全部成功。已证实该格式失败为模型 JSON 字符串含未转义引号；不是无证据的“供应商超时”。
3. **集中投屏/保存边界**：此前同规格 100 轮短测（版本 `9gBYgTHvMYT79SK_VJaXK`，后续版本新增批注修复）正常实践投屏 P95 602.784ms、草稿 2081.788ms、心跳 2050.319ms，均超标；数据对账通过。更密集的跨阶段压力另列，不能混入正常阶段稀释失败。[短测报告](projection-http-polling-100.md)。没有在最终版本独立重跑此短测，原失败保持有效的未解除风险。
4. **其他读取尾延迟**：展示读取 42 次 P95 1026.952ms；外部作品状态 6 次 P95 1057.352ms（样本少），超出普通读取 1 秒目标；两次教师扩展动作 P95 2239.483ms（样本少）也未达 2 秒写入目标。主脚本的门槛类别未包含全部这些操作，本报告按用户原约定补列，未修改原始报告掩盖差异。

全流程共 **257581** 请求，HTTP 非预期失败 **1**，约 **0.000388%**；持续阶段没有新增失败。这个总体比率不能稀释后台批注 1/40 的独立首败率。最终报告保持 `failed`。

## 修复与验证

- 投屏记录控制教师与窗口，观察端默认只读；阻止播放器初始化/远端更新反向覆盖；WebSocket 为主、低频校准与断线错峰补偿。请求有超时、取消和课程切换隔离。见 [浏览器与同步](browser.md)。
- 进度、学习事件、文档草稿及 AI 交互先持久化浏览器，服务器提交回执后移除；稳定请求 ID、完整请求指纹、重放一致；草稿服务端 CAS，冲突保留本地内容。见 [进度回执](progress-receipts.md)、[过程对账](browser-records-reconciliation.md)。
- 保存、归档与切课统一锁顺序；本进程按课程有界 FIFO，数据库仍保证跨进程正确性，教师不排入学生队列；减少冗余 SQL 往返，学生读取/时长聚合限定本人。真实 PostgreSQL 多进程、冲突、SQL 取消、回滚和权限撤销验证通过。见 [事务修复](transaction-roundtrips.md)、[本人统计范围](timing-student-scope.md)。
- 完整 AI 消息、模型原文、每次调用成功/失败/取消事实独立持久化，截断不再影响原始审计；保存与事件原子提交或持久待补写。主观批阅及后台评论均核对原文 SHA、调用标识与最终结果。见 [批阅审计](subjective-grading-audit.md)、[批注结构修复](single-review-repair.md)、[有界恢复](single-review-http-recovery.md)。
- AI 并发上限、有界排队与后台审阅容量限制；主动答疑优先于后台批注。真实模型、语音合成/识别、原生音频及媒体路径已验证。逐秒 AI 队列采样随原报告保留；本轮未测供应商长期配额或超出 40 人的容量。
- 后台生成任务查询下推安全条件，避免每 1.5 秒加载约 53MiB 历史 JSON；保留残余过滤、抢占与回滚。44 项真实 PG 等价查询及 CAS/回滚通过。见 [轮询修复](generation-job-polling-profile.md)。
- 修复生产构建追踪运行数据导致的内存耗尽；成功构建、完整类型检查、产物隔离与 CSS 检查后部署正式服务。见 [构建记录](build-tracing.md)、实际部署（本机证据：`deployment.json`）。

验证按改动分批执行，测试组存在重叠，不累加为一个虚假的唯一总数。完整性工具相关 60 项、单段 HTTP 恢复 36 项、后台轮询 23 项及其 ESLint 检查通过，最终生产构建包含全量 TypeScript 检查。此前广泛回归的原始失败结果保留；修正相关 mock 后的局部通过不改写为全套重跑通过。详见 [验收工具完整性](final-acceptance-integrity.md)；分批验证和实施过程的阶段性记录保存在本机 `notes/`。
