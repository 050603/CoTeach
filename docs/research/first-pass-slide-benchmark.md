# 首遍 PPT 生成离线对照

本实验使用固定 24 页（八类教学构图各三页），每个条件重复三次。样本包含中文、英文、精确数字、科学因果关系和程序逻辑，不读取或修改教师课程。视觉计划使用现有 fallback 并指定样本构图，测量空间预算与成稿能力；不测量全课程大纲或视觉规划模型的构图选择能力。

## 复现

```sh
# 读取正在运行服务所用的数据库、供应商加密和路由配置；不打印密钥
node scripts/run-first-pass-slide-benchmark.mjs --service-env --output=.openpbl-runtime/first-pass-benchmark-final

# 用实际 ReadonlySlideCanvas、部署 CSS 和 Chromium 读取产物并测量首稿/最终稿
node scripts/render-first-pass-slide-benchmark.mjs --watch --output=.openpbl-runtime/first-pass-benchmark-final
```

`--concurrency` 默认使用 `getClassroomSceneConcurrency()`，范围 1–5；三组均使用同一个解析后的模型和相同传输重试边界。`--model=provider:model` 可以为独立实验显式指定已有模型，不修改生产路由。`--list-models` 只输出配置的模型名称及视觉能力元数据，不调用生成 API。

生成结果逐项保存。新实验把 generation-runtime.mjs 放在各自输出目录；重新运行复用该冻结运行文件及已完成结果，不先覆盖运行文件。旧实验使用下面的显式冻结恢复入口；模型、样本及实现指纹变化时必须使用新的输出目录。不要删除失败结果来选择性提高通过率。

## 条件与记录

- `baseline`：固定提交 `843847af93106f9b6ac64f10154fb056d7141303` 中的 generation 和 prompts 源码，保留该提交链路的布局纠正及内容审核。会话开始时工作区已有未提交的“经过一次纠正后接受草稿”修改，本组不包含该修改；因此不等于会话开始时工作区或线上全部行为，不能用其失败数夸大改进。模型传输、DSL 和运行库共享本地当前依赖。快照提交记录在 metadata.json。
- `budget`：新空间预算，成稿请求只发送文本；区域草图仍在前置程序中生成，用于保持两新条件的计算输入相同。
- `sketch`：同一空间预算，额外发送程序绘制的区域草图。模型不具备视觉能力时记录不可测，不自动换模型，也不将纯文本请求计入该条件。

每条结果保存所有逻辑模型调用的原始响应、提示词、系统提示词哈希、发送图片数、耗时、首响应及最终 DSL。`calls` 是逻辑请求数；网络边界内部最多两次故障重试不等于质量返工次数。首遍统计仅使用第一条响应，不能使用 baseline 纠正后的最终稿。

播放器测量在隔离的本地 HTTP 页面中运行，读取部署 CSS、字体及原有 `ReadonlySlideCanvas`。仅禁用独立预览中不应触发的媒体生成能力，设置媒体生成开关为关闭；教学文本、图形、图表、表格、公式仍使用原组件。首响应先执行必要默认值和 KaTeX 编译，再保存 PNG、文字实际行边界和问题列表；不执行 baseline 的 balance/fit 调整。最终稿另外测量，保留原有链路中的确定性调整。读取的部署 CSS 与字体在首次测量时复制到实验目录，后续构建不改变测量环境。

静态几何结果与真实播放器结果分开保留。规则报告的碰撞不直接等于明显遮挡；区域背景包含、边缘碰撞等需要结合截图复核。精确字符串覆盖只辅助定位，改写后的正确讲解不能据此判错；知识点与数值保留仍需人工核对。

## 当前运行限制

实际 `generate-classroom` 路由在首次运行时为 `deepseek:deepseek-v4-flash`，视觉能力元数据为 false。因此原定 216 个条件样本中，有 72 个草图条件无法在该模型上完成。已配置列表中存在 `deepseek-v4-flash-vision-exp`（元数据标记支持视觉），独立单次 PNG 协议探测返回 `Model not exist.`，实际服务不可用，详见最终报告。

旧 `.openpbl-runtime/first-pass-benchmark` 中是字体统一前的先导实验，只用于排查与准备测量流程，不并入冻结实验通过率。统一 Noto Sans SC 后的冻结实验位于 `.openpbl-runtime/first-pass-benchmark-final`，具体实现哈希、完成数和错误由该目录产物给出。本轮已全部结束并完成 144 条实际尝试的独立复核：空间预算组布局 44/72（61.1%）、关键内容完整 64/72（88.9%），未达到 95% 布局和全部知识保留目标。完整数字、首稿与最终出稿区别以及已知限制见[冻结结果报告](../verification/first-pass-slides/README.md)。

## 中断后的冻结恢复

若工作区实现已继续修改，但实验的原始已编译运行文件仍存在，可显式使用 `scripts/resume-frozen-slide-benchmark.mjs --expected-runtime-sha256=<原文件SHA256> --service-env --output=<原目录>`。该入口核对原文件哈希及成稿函数等价性，保留原运行文件，在单独副本中仅替换实验指纹读取和跳过 baseline 再编译；模型、材料哈希校验及已保存结果复用不变。恢复依据写入 `resume-evidence.json`，不能删除已有失败样本。

与之配合，渲染入口传 `--reuse-frozen-runtime`，直接载入原 `render.js`、两份首稿解析模块和部署 CSS/字体快照，任何缺失都失败；不会用当前播放器重新编译而混入原实验。2026-09-14 的冻结恢复原 bundle SHA256 为 `5b77a3d80809cbde0c7cbb7b9f20aed7422754a0fae98faeff133298be892739`。生成及渲染日志写在实验目录，保留中断与恢复痕迹。

调用数和耗时只汇总已落盘逻辑请求。实验环境中断时仍在途的请求可能已发送到供应商，其完成及计费无法确认；它们不包含在已确认调用数内，网络重试也不是单独逻辑请求，因此这些统计不等于账单总请求数。

本轮截图采用严格的可见容器边界口径：少量末行越出背景也记为布局未通过，不代表每个失败都发生严重遮挡。固定提交基线与预算组使用相同口径；截图逐项说明具体缺陷，知识点保留独立判定。无任何模型响应的超时样本单列，不能描述为观察到的排版错误。

冻结实验启动后的讲授阶段时间提示、TTS 计量及公式/图表播放器修复均不混入本轮运行代码和截图；其单独验证结果不回填为本轮质量通过率。原生元素种类只描述输出产物使用情况，八类构图覆盖只表示输入覆盖；没有据此声称构图多样性已达标。导出兼容目前只有单独选择的三页验证，不能扩展成全部页面与播放器像素一致。

时延测量也有环境限制：实验尾段与同模型的另外 6 次动作调用、共享主机上的生产构建并行运行，供应商负载未隔离；中位/P95 只描述本轮已保存请求，不能当作专用环境性能或账单成本。第 24 个固定材料用单行文字表示 Python 函数，有样本照录该表示；本轮“知识保留”不等于代码可执行性验证。
