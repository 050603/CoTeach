# PBL 知识微课生成链路

本文记录当前主系统实际执行的知识讲授生成链路。知识讲授位于 PBL 项目的 `ai-learning` 阶段，职责是让学生获得后续实践所需的概念、关系、原理或技能理解。项目任务提供用途与情境，不能自动改写成知识目标。

## 1. 生成顺序

正式链路按以下顺序执行：

1. 解析并确认教师资源包，保留来源知识 ID、原文、课时和项目约束。
2. 生成并确认知识结构。20 秒无人操作只记录为 `auto-adopted`；教师主动提交才记录为 `teacher-confirmed`。
3. 规划知识讲授容量。资源包已确认课时则保持该课时；其他课程仍受外层 PBL 阶段比例约束。内部不再套用 68% 讲授比例，而是按必要解释、例子、操作或思考和小节检测分别估时。
4. 容量不足时进入持久化 `capacityReview`。该状态没有倒计时，刷新或后台恢复不能越过。教师可以按当前范围和时间继续，或退出后调整资料与课时。
5. 一次生成全课教学蓝图。蓝图先写出小节实质解释、推理连接、例子分析、概念边界、页面分工和理解标准，再编译成页面大纲。
6. 大纲审阅先呈现整节知识主线、关键解释、例子、典型误解、理解标准和时间，然后呈现页面详情。教师对已有页面的定点修改会写回蓝图，再由蓝图重新编译大纲；新增、删除或改变页面资源类型必须先回到内容设计。
7. 同一小节的普通幻灯片先并行生成课件正文。所有实际页面完成后，一次生成整节连贯讲稿并按页面返回。页面映射缺失、重复或出现未知 ID 时整节失败，并且只允许一次技术结构纠正。
8. 动作绑定消费已经确定的页面讲稿。普通强调优先按语义 ID 确定性绑定；白板、互动和视频保留专用动作链路。动作阶段不得补写核心教学解释。
9. 测验在实际讲稿完成后生成。它同时接收预定理解标准、资料边界和实际讲稿。缺少支撑单元时生成停止并报告教学覆盖不足，不能自动降低标准。每节生成 1–3 道短题，至少一道要求学生给出结论和简短理由。
10. 语音按最终语音段落生成。正文改变后旧音频、锚点和时间审计失效，不能通过变速或复用旧音频掩盖差异。

测试课与完整课使用相同蓝图、位置上下文和生成器。`test-lesson` 只限制提交给课堂生成器的页面范围，不会把第一小节误写成整门课程结尾，也不能发布为完整课程。

## 2. 内容设计契约

新生成的 `TeachingBlueprint` 使用 `schemaVersion: 2`。旧版蓝图和旧课堂仍可读取、播放，但不能作为新版生成缓存复用。

每个教学单元必须包含实际内容：

- `explanation` 写出要建立的认识。
- `mechanism` 写出前提、关系、过程以及结论成立的原因。
- `workedExample` 在需要时写明事实、对应关系、判断理由和推广边界；纯解释页可以为空。
- `conditions` 写明会改变结论的条件或边界。
- `misconceptions` 写明具体误解以及纠正理由。

“说明教学模式与教案的区别”“用例子说明联系”“澄清常见误区”属于写作任务，不能作为已完成内容。入口校验只识别明确缺失和直接的写作指令，不用字数或关键词密度宣称教学质量已经合格；解释是否充分仍由教师在大纲审阅中判断。

页面的 `teachingPlan` 必须包含本页职责、已有基础、新增认识、推理步骤、必须可见的材料和需要口头展开的内容。学习任务、案例、互动和媒体都按教学需要选用，不要求每页具有相同结构。

每节的 `understandingCriteria` 在出题前确定：

- `goals`：理解或迁移目标。
- `answerEssentials`：合格回答必须包含的认识和理由。
- `misconceptions`：典型错误表现及其对应误解。
- `supportingUnitIds`：为了达到标准必须实际讲授的单元。

理解标准会进入蓝图、页面讲稿和测验依赖检查。后续课件或讲稿遗漏内容时，标准保持不变并暴露缺口。

## 3. 三种依据的权限

教师资料和已采用的内容设计决定知识真伪、概念边界、稳定案例事实、核心推理与理解标准。补充的通行知识和教学例子单独标记来源，不能覆盖教师原文或伪装成引文。

实际课件决定当前可以看见、指向和操作什么。课件遗漏必要材料时，发布检查报告“课件缺少设计规定的必要材料”；讲稿不能为了图文一致而删掉原定解释。课件出现错误定义时，讲稿也不能沿用该错误。

实际讲稿决定学生获得了哪些学习机会。测验只能在这些学习机会内选择具体材料和问法，但答案依据与达标标准仍由资料和蓝图决定。题目讲评不能替代缺失的核心讲授。

## 4. 连贯讲稿和检查点

普通知识页按小节生成讲稿。输入包含：

- 已采用的解释、边界、稳定案例事实和理解标准；
- 小节内按顺序排列的实际课件元素；
- 每页新增认识、推理责任和承接关系；
- 全课页面位置与相邻小节职责；
- 学情、语言、时长和语音要求。

输出仍复用现有页面段落和语义引用结构，因此播放器、动作与字幕无需更换协议。小节讲稿检查点指纹覆盖生成政策、模型、小节设计、实际课件、全课位置、语言和需求。任一页面变化会使该小节讲稿检查点失效；系统不会恢复同一小节内其他页面的旧完整场景来绕过新讲稿。

较长小节当前由模型输出预算承载。超过预算时生成器报告容量或输出错误并保留已完成页面，不会截断核心解释。后续如增加分块，只能沿蓝图中已经存在的连续解释单元拆分，并传递前块实际讲稿。

## 5. 教师局部修订

课堂资源保存使用课堂修订号进行乐观并发控制。已发布课堂先分叉为草稿，再保存修改。每次保存记录 `teachingRevisionState`：基础版本、当前版本、修改类型、受影响页面和失效依赖。

- 修改讲稿：使对应音频、讲稿锚点、时间审计和测验学习机会失效。
- 修改布局：使几何相关动作绑定失效，不自动改写讲稿。
- 修改可见正文、事实或关系：使动作、锚点和测验学习机会失效；知识错误应先在内容设计中修正。
- 删除页面：同时按视觉和讲稿变更处理。

讲稿 AI 改写读取同一小节的实际完整讲稿作为只读上下文，只能返回目标页已有语音 ID 的补丁。未请求段落、其他页面、白板内部讲稿和非语音动作保持不变；目标段落在生成期间被人工修改时，服务端拒绝覆盖。新增或改写的语音一律移除旧音频元数据并标记重新生成。

## 6. 教师状态、学生内容和发布门禁

`teachingAdoptions` 区分 `auto-adopted` 与 `teacher-confirmed`，并绑定采用内容的修订指纹。自动采用不产生教师确认签章。

资源包原文、蓝图、采用记录、修订状态、时间审计、生成轨迹和质量审查都属于教师侧数据。学生资源快照会移除这些字段。学生课件、讲稿、字幕、语音、互动和题目仍可正常讨论“证据”“核实”等学科内容，但不得出现证据状态、审查记录、确认记录或内部枚举。

发布、模板发布、创建课堂实例和开课都调用统一的教师终审门禁。门禁在验证教师签章和内容签名后，仍会针对当前课堂重新计算确定性的结构阻断项，包括：

- 必需知识或页面缺失；
- 小节理解标准缺失；
- 页面设计仍是任务清单或缺少核心论证；
- 课件缺少蓝图规定的必要可见材料或必要媒体；
- 教师管理信息进入学生内容；
- 资源包确认、课时或适配授权失效；
- 确定的画布越界、遮挡或不可读文字。

阻断问题可以保留为可预览草稿，但不能通过接受建议、旧教师签章或可选 AI 检查未运行来发布。语义疑点和一般版式建议仍由教师判断；本轮没有增加自动多轮教学审查。

## 7. 版本与恢复边界

当前关键版本为：

- 课程生成契约：`generationContractVersion: 3`
- 教学蓝图：`schemaVersion: 2`
- 实质教学简报：`substantive-section-brief-v6`
- 整节讲稿：`section-continuous-narration-v7`
- 首稿课堂政策：`course-first-pass-v8-section-narration`
- 测验依赖：`predeclared-understanding-standard-v3`

生成调用的基础重试仍有明确上限。恢复任务只复用模型、输入和政策指纹全部匹配的完整检查点；旧产物不能冒充新版缓存。已有课程不会因版本升级自动重生成。
